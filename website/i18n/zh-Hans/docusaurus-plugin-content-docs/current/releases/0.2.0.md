# Req 0.2.0

## 安装或升级

在已配置 Mojo 的 Pixi 工作区中执行：

```sh
pixi workspace channel add --prepend https://repo.prefix.dev/modular-community
pixi add "req==0.2.0"
```

版本固定命令也可用于从 Req 0.1.0 升级。该命令要求社区频道已上架 0.2.0；
上架前请使用[源码构建](https://mojoto.github.io/req.mojo/zh-Hans/docs/development)。
Req 使用 Mojo **1.1.0**，支持 Linux x86-64、Linux ARM64、macOS ARM64。
Pixi 安装匹配的编译器和原生依赖，使用 `pixi run mojo main.mojo` 运行，
无需构建 C 库或添加链接参数。

## HTTP/2、代理与连接池限制

```mojo
import req


def main() raises:
    var owner = req.Client(
        http2=True,
        limits=req.Limits(max_connections=10, max_keepalive_connections=5),
        timeout=req.Timeout(connect=3.0, read=10.0, write=10.0, pool=2.0),
    )
    with owner.context() as client:
        var response = client.get("https://example.com")
        response.raise_for_status()
        print(response.http_version)
```

HTTP/2 需要显式开启，且 libcurl 构建必须包含 HTTP/2 支持；默认允许回退到 HTTP/1.1。
仅 HTTP/2 模式（`http1=False, http2=True`）要求 libcurl 8.10 或更新版本。
添加 `proxy="http://127.0.0.1:8080"` 使用显式 HTTP/HTTPS 代理，
或用 `trust_env=True` 读取代理与 CA 环境配置。
连接池容量等待由 `Timeout.pool` 控制，超时抛出 `PoolTimeout`。
详见[网络配置](https://mojoto.github.io/req.mojo/zh-Hans/docs/networking)。

## 文件与 multipart 上传

通过 `body=req.RequestBody.from_file("report.csv")` 增量发送文件，
也可以把 multipart 文件与普通字段组合发送：

```mojo
import req


def main() raises:
    var files = List[req.UploadFile]()
    files.append(req.UploadFile.from_bytes(
        "file", req.encode_utf8("hello\n"),
        filename="hello.txt", content_type="text/plain",
    ))
    var response = req.post(
        "https://httpbin.org/post",
        files=files,
        data=req.QueryParams("tag=mojo&tag=http"),
    )
    response.raise_for_status()
    print(response.status_code)
```

文件和字节请求体可以重放。`RequestBody.from_chunks(...)` 是有限字节块列表，
默认只能发送一次；消费后再次发送会抛出 `StreamConsumed`。
参数组合和重定向行为见[上传 API](https://mojoto.github.io/req.mojo/zh-Hans/docs/api/uploads)。

## 按字节、文本与行消费流

```mojo
import req


def main() raises:
    with req.stream("GET", "https://example.com") as response:
        response.raise_for_status()
        for line in response.iter_lines():
            print(line)
        print(response.elapsed())
```

`iter_bytes()` 返回解码字节，`iter_raw()` 返回去除 HTTP 传输帧后的原始编码字节，
`iter_text()` 增量解码文本。上下文退出也会关闭未完全消费的响应。
详见[流式响应](https://mojoto.github.io/req.mojo/zh-Hans/docs/streaming)。

## 钩子、传输层与响应元数据

- [EventHooks](https://mojoto.github.io/req.mojo/zh-Hans/docs/api/hooks) 按顺序执行请求和响应回调，跟随重定向时每一跳都会执行。
- [MockTransport 与自定义传输层](https://mojoto.github.io/req.mojo/zh-Hans/docs/api/transports) 允许测试直接提供响应，无需网络服务。
- `response.history` 保留已关闭的中间响应；未跟随重定向时，
  `response.next_request` 提供已准备的下一跳请求。`response.cookies` 是单次响应的快照。
- `response.elapsed()` 返回从发送到读完或关闭的秒数；提前访问抛出 `StreamNotRead`。

## 默认行为与 0.1.0 升级说明

现有基本请求保留默认行为：验证 TLS、HTTP/1.1、不跟随重定向、各阶段超时五秒。
`Timeout(seconds)` 和 `Timeout.disabled()` 现在也包含连接池阶段。
只有 `trust_env=True` 才读取环境路由配置。
HTTP 4xx/5xx 仍需调用 `raise_for_status()` 才转为错误。

Client 仍用于单线程场景；暂不提供 Async API、总请求截止时间和可配置的应用层自动重试。
每个 worker 使用独立 Client，退出客户端上下文前读完或关闭响应。
