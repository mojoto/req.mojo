# Req 0.2.0

## Install or upgrade

In a Pixi workspace already configured for Mojo:

```sh
pixi workspace channel add --prepend https://repo.prefix.dev/modular-community
pixi add "req==0.2.0"
```

The version-pinned command also upgrades a workspace using Req 0.1.0.
It requires 0.2.0 to be available in the community channel; before publication,
use the [source build](https://mojoto.github.io/req.mojo/docs/development).
Req uses Mojo **1.1.0** on Linux x86-64, Linux ARM64, and macOS ARM64.
Pixi installs the matching compiler and native dependencies. Run with
`pixi run mojo main.mojo`; no C build or linker flags are needed.

## HTTP/2, proxies, and pool limits

```mojo
import req


def main() raises:
    var owner = req.Client(
        http2=True,
        limits=req.Limits(max_connections=10, max_keepalive_connections=5),
        timeout=req.Timeout(connect=3.0, read=10.0, write=10.0, pool=2.0),
    )
    with owner.context() as client:
        var response = client.get("https://example.com")
        response.raise_for_status()
        print(response.http_version)
```

HTTP/2 is opt-in and requires libcurl with HTTP/2 support; HTTP/1.1 fallback
remains enabled. HTTP/2-only mode (`http1=False, http2=True`) requires libcurl
8.10 or later. Add `proxy="http://127.0.0.1:8080"` for an explicit HTTP/HTTPS
proxy, or `trust_env=True` to read proxy/CA environment configuration.
Pool waits use `Timeout.pool` and raise `PoolTimeout`.
See [network configuration](https://mojoto.github.io/req.mojo/docs/networking).

## File and multipart uploads

Send a file incrementally with
`body=req.RequestBody.from_file("report.csv")`, or combine multipart
files and ordinary fields:

```mojo
import req


def main() raises:
    var files = List[req.UploadFile]()
    files.append(req.UploadFile.from_bytes(
        "file", req.encode_utf8("hello\n"),
        filename="hello.txt", content_type="text/plain",
    ))
    var response = req.post(
        "https://httpbin.org/post",
        files=files,
        data=req.QueryParams("tag=mojo&tag=http"),
    )
    response.raise_for_status()
    print(response.status_code)
```

Files and byte bodies are replayable. Finite `RequestBody.from_chunks(...)`
sources are one-shot by default; resending one after consumption raises
`StreamConsumed`. See [uploads](https://mojoto.github.io/req.mojo/docs/api/uploads)
for body combinations and redirect behavior.

## Stream bytes, text, and lines

```mojo
import req


def main() raises:
    with req.stream("GET", "https://example.com") as response:
        response.raise_for_status()
        for line in response.iter_lines():
            print(line)
        print(response.elapsed())
```

Use `iter_bytes()` for decoded bytes, `iter_raw()` for original content-encoded
bytes without HTTP transfer framing, and `iter_text()` for incremental text
decoding. Context exit closes partially consumed responses too.
See [streaming](https://mojoto.github.io/req.mojo/docs/streaming).

## Hooks, transports, and response metadata

- [EventHooks](https://mojoto.github.io/req.mojo/docs/api/hooks) run request and
  response callbacks in order, including each followed redirect.
- [MockTransport and custom transports](https://mojoto.github.io/req.mojo/docs/api/transports)
  let tests supply responses without a network server.
- `response.history` retains closed intermediate responses.
  `response.next_request` exposes the next prepared request for an unfollowed
  redirect. `response.cookies` is a per-response snapshot.
- `response.elapsed()` reports seconds from sending until reading or closing
  completes; accessing it earlier raises `StreamNotRead`.

## Defaults and upgrading from 0.1.0

Existing basic request calls keep their defaults: verified TLS, HTTP/1.1,
no followed redirects, and five seconds per timeout phase.
`Timeout(seconds)` and `Timeout.disabled()` now include the pool phase.
Environment routing remains off unless `trust_env=True`.
HTTP 4xx/5xx requires `raise_for_status()` to become an error.

Clients remain single-threaded. There is no Async API, overall request deadline,
or configurable application retry policy. Keep one Client per worker and
consume or close responses before releasing its context.
